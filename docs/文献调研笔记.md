## 二、机器人构型

3. **板载电路单元**：两块堆叠 PCB + 排针连接（Movie 1 约 12–14 秒标注 Stacking design / Pin header / Onboard circuit unit）。
4. **底部光学位置传感器模组**：传感器芯片 + FPC + 镜头，朝下看地面（Movie 1 约 21–23 秒标注 Position sensor / FPC / Lens；正文未写型号，思路类似"光电鼠标测位移"）。

## 三、驱动原理与运动算法

- **振动原理**：一阶弯曲共振 ~31.5 kHz，足端走出 OY/OZ 平面内斜椭圆轨迹（仿真 11.15/8.83 μm，实测 10.03/9.31 μm @80 Vpp）——主文 Fig. 2；前四阶模态 31.79/68.71/117.24/192.70 kHz（Fig. 2a）。
- **OVS / LBS 双状态**：腿工作在谐振点附近 = **OVS（最优振动状态，出推进力）**；工作在 ~10 kHz 非谐振点 = **LBS（低频弹跳状态，高频减摩擦、几乎不出力）**——主文。三条腿谐振频率略有差异：leg-1/2/3 = 31.51/31.46/31.66 kHz（主文 Fig. 1e 图注，审评文件中原文引用）。**这两个频率即固件要写的核心参数，来源是论文的激光测振标定实验（平台 Fig. S5，Movie 2）。**
- **全向运动合成**：单驱动模式（1 腿 OVS + 2 腿 LBS）给 3 个基本方向，双驱动模式（2 腿 OVS + 1 腿 LBS）给 3 个合成方向，共 6 个基向量；任意方向靠**轨迹插补算法**在两基向量间交替逼近（插补参考角 α + 切换阈值），偏航偏差由机载姿态传感器实时补偿——补充 Note 2（第 5–6 页）+ Fig. S4；动画演示 Movie 1 Part II 约 32–40 秒。
- **力分配系数**：K(θ) = sin(θ)/sin(120°−θ)（正弦定理推导），功率与能耗效能 η(θ) 分析——补充 Note 5（第 10–15 页）+ Fig. S8。
- **RCmin 指标**（零转弯半径的重定向代价；全向 = 1，有转弯半径 > 1）——补充 Note 1（第 3–4 页）+ Fig. S1。回应审稿人"为什么要全向"而定义的指标，值得精读。

## 九、程序烧录方式

- **ESP32 不用 ST-Link / J-Link**：那是 STM32 等 ARM Cortex-M 芯片的 SWD 调试探针。ESP32 出厂 ROM 自带 UART 下载引导：复位时拉低 strapping 引脚 GPIO0 进入下载模式，由乐鑫官方 esptool（`idf.py flash`）经 UART0 的 TX/RX 把固件写入 Flash。
- **开发板上的 USB 口**：本质是板载 CP2102/CH340 USB-UART 桥芯片，配合 DTR/RTS 自动控制 EN/IO0 实现"一键下载"，并不是调试器。
- **自制微型板的做法**（工程惯例，论文未写明）：不留 USB 座，留 6 个焊盘测试点（3V3 / GND / TX / RX / EN / IO0），装配前用探针夹具连接 USB-UART 模块烧录，占板面积几乎为零。
- **无线 OTA**：ESP32 原生支持 Wi-Fi OTA 升级（ESP-IDF 有现成例程）；本项目本来就有 TCP/HTTP 通信栈，样机联调的常见流程 = 首次有线烧录 + 后续无线 OTA 迭代。
- 验证途径：读开源仓库的实际实现。

## 十一、视觉系统的真实角色

- 相机在**地面上、上帝视角**；机器人运动**不依赖视觉**，靠机载光电位置传感器（航位推算）+ IMU，执行 PTP 导航。
- 视觉的三个实质职能：①人机交互（视频流里点目标点、框选机器人）；②多机场景的公共位置源（某台位置传感器失效时接管，Movie 12 Part I 演示）；③显微应用中的成像"眼睛"（拼接靠它）。
- 注意：Movie 1 是 3D 动画、Movie 2 是激光测振仪画面，其余多为顶视相机实拍。

## 十二、图像拼接与工业应用背景

**图像拼接找键合线缺陷是什么**：引线键合（wire bonding）是芯片封装关键工序——用直径 15–50 μm 的金/铜丝把裸芯片焊盘连接到基板焊盘，断线/塌线/虚焊 = 电路断路 = 芯片报废，因此封装厂标配 AOI（自动光学检测）。高倍显微镜视场小（1500× 下仅零点几毫米），本项目的做法：机器人当精密移动平台 → 0.56 μm 步进走网格逐格拍重叠小图 → PC 特征匹配拼接全景 → 全景上发现疑似缺陷 → 高倍工位微步进精确定位确认。与手机全景拍照、病理切片扫描仪同原理。

**像素坐标标定（问题 5 延伸）**：需要专门写标定，标准做法分两层——①像素→毫米：俯视平面场景用**单应性矩阵**，放已知尺寸标定板（论文画面中的 5 cm 比例尺即此用途），取 4 个已知世界坐标的角点，`cv2.getPerspectiveTransform` 求 3×3 矩阵，此后任意像素坐标乘该矩阵即得毫米坐标；②镜头畸变校正：广角镜头先经 `cv2.calibrateCamera`（棋盘格多图）求内参与畸变系数，`cv2.undistort` 校正后再测。OpenCV 几十行即可，机器视觉岗位的基本功。

## 十三、多机通信与坐标解算

- **网络拓扑**：所有设备连同一个 Wi-Fi 路由器；上位机为服务器，每台机器人一个客户端，各持 TCP/WebSocket 长连接（各 有 IP）。"私发" = 服务器向指定连接定向写帧；"群发" = 向多条连接写同一帧——与微信群同构（微信服务器 = 上位机，群成员 = 机器人）。消息为带 robot_id 的 JSON/二进制帧，如 `{"id":0,"type":"target","x":180.0,"y":90.0}`。协议细节论文未公开，此为标准实现推断；已发布上位机实际走 HTTP（见第十节）。
- **坐标链路**：上位机经相机标定建立世界系（毫米）→ 开机时把机器人初始位姿发给它 → 机器人靠机载位置传感器积分 + IMU 航向，在**同一世界系**持续自估 (x, y, θ)（航位推算）→ 视觉周期性校正漂移；位置传感器失效时由视觉位姿接管。
- **方向解算示例**：目标 (180, 90)，自估 (100, 50)、θ=15° → Δ=(80, 40)，期望航向 θ_d=atan2(40,80)=26.6° → 航向误差 11.6° → 机体无旋转自由度，在夹住 26.6° 的两基向量间按 K(26.6°)=sin26.6°/sin93.4°≈0.45 分配：腿 1 全力 OVS、腿 2 出 45% 力 OVS、腿 3 进 LBS → 每步更新位姿重复，直至 |Δ|< 到达半径。全程 MCU 只消费数字，无任何图像进 MCU。
- **"上位机发位置给 MCU"的两种情况**：正常运行只发**目标点**与（多机时）**领航者位姿**，机器人自身位置自己算；位置传感器失效时，上位机把视觉解算的位姿周期性下发接管（multi-sensor integration 的真实含义：机载定位为主、视觉定位兜底的双通道冗余）。

## 十四、驱动信号与调速：方波、OVS/LBS 与三个旋钮

**为什么用方波不用正弦波**：论文明确三路输出为方波（主文 "three independent square-wave outputs"；Note 6 原文高压运放 "configured as a comparator"）。两个原因：①腿是高 Q 值谐振结构，天然是个机械带通滤波器——方波的 3/5/7 次谐波（94.5/157.5 kHz…）远离各阶振型（68.7/117.2 kHz…），全被衰减，足端仍走出干净的斜椭圆简谐轨迹；②60 Vpp 正弦需要线性功放（效率低、发热大、占体积），方波只需比较器+开关式升压，效率高、电路简单——"用机械谐振换掉线性功放"是微型化的关键一笔。

**OVS/LBS 是状态，不是波形上的位置**：两者是腿的两种工作状态，区别在激励频率于幅频曲线上的位置——OVS 踩在谐振峰顶（~31.5 kHz，足端 ~10 μm 椭圆，出推进力）；LBS 固定在 10 kHz 平坦区，小幅弹跳、几乎不出推进力，作用是让足端周期性离地、把静摩擦变成动摩擦、降低平均正压力，**给 OVS 腿减阻**（Methods "high-frequency friction-reduction effect"；LBS 也耗功：60 Vpp 时 313.8 mW、30 Vpp 时 74.0 mW）。修正直觉：OVS 在**频域幅频曲线**的峰顶，不在时域波形的波峰上。

**两组正交开关，可任意组合**：单驱/双驱（选 6 个方向中的哪个）× 连续/掩模（持续跑还是逐步迈）：

| | 连续激励（宏观快速） | 10 Hz 掩模步进（微观） |
|---|---|---|
| 单驱（1 腿 OVS） | 基本方向 7.73–24.23 mm/s | 同样有微步 |
| 双驱（2 腿 OVS） | 合成方向 12.74–30.08 mm/s | 最小步距 0.56 μm（#1+#2 出力） |

**调速旋钮按模式各不同**（Fig. 3c–e 的核心结论）：单驱连续→**调频率**（灵敏度 <0.52 mm/s/Hz）；双驱连续→**调电压**（0.19–0.52 mm/s per Vpp，起振门槛 30 Vpp）；掩模步进→**占空比定步距**（0.29–3.53 μm/1%）、**掩模频率定步频**（10 Hz = 每秒 10 步）。全系统共四个旋钮：31.5 kHz 载波、10 kHz LBS、10 Hz 掩模、0–60 Vpp 电压，正交调节。

**"切换成本低"的原文含义**：两模式仅驱动信号形式不同——连续模式是 31.5 kHz 方波持续输出，微观模式是**同一个方波被 10 Hz 低频掩模门控**，不改硬件、不换接线，固件里只是输出使能按 10 Hz 开关。算量级：掩模周期 100 ms、占空比 1% = 每次放开 ~1 ms ≈ 31 个载波周期，足端振 31 下挪 0.56 μm。

**声学延伸疑问**：Methods 的静音约束 "谐振频率 > 20 kHz" **只约束主力振动**（31.5 kHz 超声、不可闻）。LBS 的 10 kHz 严格说在可听段（20 Hz–20 kHz），但振幅小、声压弱，实际大概率是一声微弱高频丝鸣——**留待实物实测验证**；10 Hz 掩模听到的不是"10 Hz 的音"（低于音调下限 20 Hz），而是足端每秒 10 次拍地的机械嗒嗒声；掩模边带（31.5k±10 Hz）仍在超声区。

## 十五、基向量与插补：用 6 个"档位"拼出任意方向

- 6 个基向量 = 3 个单驱基本方向 + 3 个双驱合成方向，彼此隔约 60°；双驱再调两腿力分配比 K(θ)=sinθ/sin(120°−θ)（Note 5 正弦定理闭式解），又得 6 个不对称角 → 共 12 个离散方向（30° 分辨率，实测偏航 0.2°–5.6°）。
- "基"取线性代数之意：任意目标方向 = 相邻两个基向量的加权组合。机器人**没有旋转自由度**，不能连续转向——基向量是全部"词汇"，插补是"造句"：先沿组合 B 走（插补角 α 递减），到阈值切组合 A（α 递增），如此交替、锯齿式逼近目标直线；阈值越小轨迹越密、切换越频繁（Note 2 原文逻辑）。行进中 IMU 偏航角实时补偿进参考角。
- 一句话：插补算法 = 双基向量交替 + K(θ) 力分配查表 + 偏航补偿的状态机，无任何神秘成分。

## 十六、"自主导航"的边界：机载闭环航点导航

- 自主的是**执行层**四件事（Fig. 5）：自定位（光流积分 + IMU 航向）、自选驱动（模式/基向量/分配比）、自纠偏（PID + 插补角补偿）、自判到达（距离 < 到达半径，逐点推进）。原文 "the entire process is performed autonomously by the robot"。
- 不自主的是**决策层与环境层**：目标点由人给定（画"6"字/三角形 = 人给点序列）；无环境感知、无避障、无路径规划（PTP 是 single-cycle，每次迭代只看目标点与当前位置）；迷宫实验原文 "user guides the robot"（人引导，霍尔只报检查点）；速度环仍开环（闭环速度控制 = 作者自列 future work）。
- 分层定位：开环遥控（字母轨迹、圆轨道续航）→ **闭环航点导航（本文所处层）** → 路径规划+避障（无）→ 任务级自主（无）。
- 敢用"自主"一词的理由：对照自家开环方案（"manual state determination"，人要不断发指令、人要判断状态）是实质跃迁；多机场景领航者/跟随者全程无人工介入运动控制。

## 十七、径向分布与零旋转扭矩

- τ = r × F：三条腿推力沿"轮辐"指向圆心，力线穿过机身中心、力臂为零 → 任意组合都是纯平移力，天生产生零旋转扭矩（Discussion 原文）。对照组：切向布置的构型靠力矩平衡走直线，任何不对称即生不可预测偏航（引言批评的 prior work "susceptible to undesirable yaw and path deviation"）。
- 实际偏航的来源 = 加工/装配误差产生的**寄生扭矩**（Discussion 限制 iv 自认）+ 三腿谐振频率差异（31.51/31.46/31.66 kHz → 同激励下出力不等）+ 摩擦各向异性。两道防线：①对称构型让标称扭矩为零（结构层）；②IMU 实时测偏航 → 补偿插补角 → PTP 闭环纠偏（控制层）。
- 代价与卖点一体两面：零扭矩 ⟹ 永不主动旋转 ⟹ 所有换向都是纯平动 ⟹ "零转弯半径"。

## 十八、PID：从循迹小车到三足机器人

| | 循迹小车 | 三足机器人 |
|---|---|---|
| 执行器 | 双电机差速，连续可调 | 三腿 OVS/LBS + 分配比（离散切换 + 连续插补） |
| 转向 | 有旋转自由度 | 无——"转向"靠两基向量配比当**虚拟方向盘** |
| PID 输出 | 直接=占空比 | 先翻译成插补角/分配比修正，再查表执行 |
| 增益 | 近似恒定 | 随方向变（η(θ) 下降、电压灵敏度差近 3 倍）→ 需按方向调度 |
| 死区 | 无明显死区 | 30 Vpp 起振门槛 → 必须处理积分饱和 |
| 反馈 | 灰度传感器直接给偏差 | 光流积分+IMU 均会漂（反馈是估计值，需外部源周期校正） |
| 被控对象 | 电机近似一/二阶系统 | 尖锐谐振系统，三腿谐振峰各不相同 |

- 回路组织（Fig. 5a 流程）：外环——位置误差向量 → 期望航向 θ_d = atan2(Δy, Δx)；内环——e = θ_d − θ_IMU 进 PID；输出修正插补参考角 α 与 K 分配比。
- P/I/D 各吃什么数据：**P** = 当前角度误差（IMU 航向 vs 期望航向），偏多少往回掰多少；**I** = 误差时间累计，专治恒定偏航（腿不对称、摩擦各向异性——没有 I 会走出固定半径的圆弧）；**D** = **陀螺仪角速度原始值**（工程技巧：不要对角度数值做差分，噪声大），阻尼插补切换带来的锯齿振荡。

## 十九、通信链路：为什么 WiFi/HTTP/TCP/WebSocket，数据到底怎么传

- 为什么不是蓝牙串口：传的不止"位置角度"——是双向多参数流（下行：模式/目标点/电压/频率/占空比；上行：位姿/电池电压/温度/气体/霍尔事件），且要支撑多机星型拓扑（1 上位机 + N 机器人 + 手机）、iOS 不开放蓝牙 SPP、ESP32 的 WiFi 白送、相机视频流同在一局域网、HTTP 可用浏览器/curl 裸调（README API 的调试便利来自这里）。
- 三协议分工（Fig. 5a 原文）：**TCP** = 控制链路（手机↔机器人）、**WebSocket** = 状态广播（机器人主动推送）、**HTTP** = 功能指令（请求-应答）；已发布的上位机实际用 HTTP。
- 数据本质 = **字节 = 文字**，不是"频率代表某个变量"。报文逐层装信封：应用层文字 `POST /cmd {"volt":45}` → TCP 加序号/校验（不丢、保序、自动重传）→ IP 加地址 → WiFi 射频调制发波；接收端逐层拆信封。"协议" = 双方事先约定的文字格式；"看懂" = 回调函数里的字符串/JSON 解析。
- **要手写的只有最上层**：无线电与 TCP/IP 由 WiFi 硬件 + lwIP 协议栈（ESP-IDF 内置现成库）完成；httpd 组件负责 HTTP 报文拼解；cJSON 负责解析——业务代码只剩"从 `{"volt":45}` 里抠出 45 存进变量"。
- 自学路径：B 站「湖科大教书匠 计算机网络」（分层/TCP 动画，治抽象）→「正点原子 / 安信可 ESP32 教程」WiFi 章节 → 30 分钟动手实验（DevKitC 开 TCP 服务器 + PC「网络调试助手」互发文字）→ Wireshark 抓包亲眼看信封。

## 二十、固件架构：事件驱动 + 状态机

核心认知："代码写死的只是它能听懂的**词汇表**；收到指令只是**改变量**；波形由 PWM/升压外设自动输出，CPU 平时闲着。" 论文固件未开源，以下为按 Note 2/6 逻辑重构的教学示意（**非论文代码**）：

```c
// ---------- 共享状态：通信侧写，控制侧读 ----------
typedef struct {
    uint8_t mode;          // 0停止 / 1连续(宏观) / 2步进(微观)
    uint8_t ovs_legs;      // 位图：哪些腿出力，0b011 = leg1+leg2(双驱)
    float   voltage;       // 0~60 Vpp
    float   f_ovs[3];      // 三腿各自的谐振频率（标定参数表写入）
    float   duty;          // 掩模占空比(仅步进模式)
} cmd_t;
static QueueHandle_t cmd_q;   // FreeRTOS 队列：通信与控制任务间的传送带

// ---------- 通信侧：lwIP 协议栈收包后触发 ----------
// 上位机执行: POST /cmd  {"mode":1,"legs":3,"volt":45}
esp_err_t on_cmd(httpd_req_t *req) {
    char buf[128];
    httpd_req_recv(req, buf, req->content_len);   // 协议栈已拼好完整报文
    cmd_t c = parse_json(buf);                    // "词汇表"在这里
    xQueueOverwrite(cmd_q, &c);                   // 只更新目标值
    httpd_resp_send(req, "OK", 2);
    return ESP_OK;
}

// ---------- 控制侧：独立任务，上电起常跑 ----------
void control_task(void *arg) {
    cmd_t c = {0};
    for (;;) {
        xQueuePeek(cmd_q, &c, portMAX_DELAY);
        for (int i = 0; i < 3; i++) {
            bool ovs = (c.ovs_legs >> i) & 1;
            pwm_set_freq(ch[i], ovs ? c.f_ovs[i] : 10000);  // OVS踩谐振峰/LBS 10kHz
            boost_set_vpp(ch[i], ovs ? c.voltage : 30);      // 电压旋钮
            mask_enable(ch[i], c.mode == 2, 10.0f, c.duty);  // 信号形式旋钮
        }
        run_navigation_tick();   // PTP模式：读位姿→算偏差→PID→改ovs_legs
    }
}
```

数据流一句话链：网卡中断 → 协议栈拼包 → 回调解析 → 队列 → 控制任务 → 改 PWM/升压外设寄存器 → 硬件自动出方波 → 腿振动。换蓝牙串口只改前两级（UART 中断 → 环形缓冲），后面全部不变。

| 传感器 | 给 MCU 的原始数据 | 用途 |
|---|---|---|
